# 1. Product Vision

AI Investment Desk is intended to be a personal AI-powered investment portfolio tracking, financial research, and investment intelligence platform.

The application should help users:

- Monitor and analyse their investment portfolios.
- Research companies and understand their businesses.
- Collect and understand financial news.
- Analyse financial statements and company valuations.
- Identify investment and portfolio risks.
- Understand financial markets and macroeconomic conditions.
- Conduct comprehensive investment due diligence.
- Compare investment opportunities.
- Receive personalized investment research and portfolio insights.

The application is an investment research and decision-support tool, not a broker or trading platform.

It must not execute trades or make unsupported guarantees about investment returns.

# 2. Preferred AI Architecture

I have decided to use the LangChain ecosystem.

The preferred technologies are:

- LangChain: Agent development, model integrations, tool calling and reusable components.
- LangGraph: Multi-agent orchestration, workflow management, state, checkpointing, and execution control.
- Deep Agents: Complex autonomous research, planning, delegation, subagents and context management.
- LangSmith: Optional tracing, monitoring, debugging and agent evaluation.

Do not introduce Microsoft Agent Framework.

Do not assume all three LangChain components must be used everywhere. Evaluate where each is actually appropriate.

The existing application supports or intends to support multiple LLM providers, including:

- Google Gemini
- Anthropic Claude
- Ollama

Inspect the current implementation and determine how to preserve model-provider flexibility.

Avoid unnecessary vendor lock-in.

# 12. Audit Rules

These rules are mandatory:

1. Inspect the actual code before making architectural conclusions.
2. Never claim a feature exists based only on filenames, comments or documentation.
3. Distinguish implemented, partially implemented, configured but unused, and missing functionality.
4. Reference actual file paths and relevant classes/functions wherever possible.
5. Identify dead code and unused integrations.
6. Avoid unnecessary abstractions and excessive numbers of agents.
7. Reuse existing working components wherever possible.
8. Keep deterministic financial calculations outside LLM reasoning.
9. Preserve existing Gemini, Claude and Ollama flexibility where feasible.
10. Do not introduce Microsoft Agent Framework.
11. Do not install dependencies.
12. Do not modify files, configurations or databases.
13. Do not expose secrets or print API keys during inspection.
14. Clearly separate confirmed findings from recommendations and assumptions.

If the project is too large to inspect in one pass, work module by module and maintain an inventory of inspected and uninspected areas.
